# Desktop connection center

Visitor mode: Operate. Technically comfortable desktop users sign in to their embedded Tailscale device, choose an authorized exit, select split or global routing, and explicitly connect. Keep the everyday connection path compact and put node inspection in its own destination.

## Direction contract

THESIS: Exit Nodes is the first destination and opens directly to a magpie-style Exits list: one row per embedded device (the optional legacy `main` profile first when present), each opening its own list-only picker with individual Ping actions. A toolbar above the list places Add exit on the left and the current default exit on the right, without an exit-count statistic. The connection switch sits at the top right. Settings owns Split/Global: Global runs only `rules.global_exit`; Split selects `rules.default_exit` independently of `rules.final` and exposes rule groups for multiple exits. The Default/Global exit badge follows the active mode's saved selector. Existing Split rules survive mode changes. Exit Nodes and Logs sit at the top; Settings remains pinned at the bottom and expands in place into a second-level submenu (General, Network, DNS, Routing rules, Advanced, About & updates) instead of an in-page tab bar.

OWN-WORLD: Preserve blue actions, neutral light/dark system surfaces, window chrome, and semantic state colors. Density, sidebar layout and typography follow the user's magpie reference: the platform UI face (SF Pro / Segoe UI with PingFang SC / Microsoft YaHei) at 13px body, 28px navigation and controls, a muted "Parent / Page" titlebar path that replaces visible in-page headings, label-left/control-right settings rows, and a sidebar footer status line. Retain monospace for YAML, logs and code-like configuration fields. Cards use 16px continuous corners (`superellipse(1.6)` where supported, rounded fallback); dialogs use 20px. The page or whole dialog owns scrolling, never a card inside it. Node rows have no selected or hover fill and no pointer blue focus box; visible keyboard focus is retained. Segmented controls lift the chosen segment. Every form dropdown uses the shared `select.js` combobox/listbox, including Log level's unboxed text trigger; dropdown options retain their keyboard/pointer active highlight and selected green check. The picker uses a single rounded Card list surface with internal dividers and 34px single-line rows. The user's direction fixes the order to a leading plain green Phosphor Check only when selected (an empty reserved slot otherwise), node name, right-aligned latency in an 80px column, and an explicit Ping button at the far right. The titlebar update action disappears once the app is up to date. No IP address, server icon, separate status/path column, or radio is shown. Latency is green through 500ms, amber above 500ms through 1000ms, and red above 1000ms. Ping runs independently; clicking the name or checkmark selects through the existing confirmation flow. Names truncate in narrow windows without horizontal scrolling. No new visual identity or illustration.

STORY: Add an exit or sign in to a saved profile, open its node picker, select and confirm, then connect. Cancel, Escape and backdrop clicks discard the picker selection; dismissing is blocked while saving. Pointer drags that start inside do not dismiss it. Node confirmation and settings saves keep a disconnected app idle and reconnect an active session. Adding an exit stops the active connection, saves a new additional profile, opens browser authorization to choose its Tailnet, then opens its picker. Add has no preliminary name dialog. Confirming the first node binds the Tailnet guard and names the exit `<exit-device-name>@<network name>`. Automatic names follow later node choices while profile IDs and existing custom labels stay intact. Remove exit disconnects, logs out only that client, removes the local profile and its explicit route groups, adjusts affected selectors and leaves the app stopped. The remote Tailnet device record remains. Ping measures the embedded device's round-trip latency independently of selection, with direct/relay, pending, failure, and retry states.

FIRST VIEWPORT: A narrow persistent sidebar flanks the full-width Exit Nodes workspace. A compact toolbar precedes the list below the titlebar: Add exit on the left, and a compact shared text dropdown showing the saved Split default proxy exit or Global exit, or Not set, on the right. Clicking opens the menu directly, without an edit dialog. Choosing saves immediately; idle apps stay disconnected and active sessions reconnect. Keeping the current choice does not write or reconnect. Exit dropdowns show names without appended IP addresses. No exit count appears. The titlebar orders connection status, an unboxed shared Rule-based / Global (Kill-Switch) dropdown for the existing Split/Global modes, the master switch, and Refresh at the far right. Default-exit information stays above the list. The shortcut saves immediately and reconnects active traffic; turning it off retains Split policy. It is disabled for drafts, busy operations or a missing target gateway during active traffic, and it never implies persistent firewall protection after disconnect. Turning on without a default opens a choice dialog with no preselected option. The user chooses and confirms before saving and connecting; Cancel/Escape changes nothing, failures stay retryable, revision conflicts block saving, and dismissal is blocked during saving. Settings drafts block connection. Existing offline defaults are never silently replaced. There is no connection card or mode control above the list. The modal contains the device identity with Sign in only when needed, online/unavailable rows with individual Ping, and confirmation. Every saved exit, including `main` and the last exit, has Remove exit in a separate bottom section. There are no standalone switch-network or sign-out controls, search field, manual entry or picker Refresh action. The page and whole modal own scrolling, with no nested card scroller. Settings and Logs remain independent pages. Routing mode, the active mode's exit selector, unmatched traffic and rule source share one card with equal-height rows; source help and errors sit below the card.

FORM: Desktop connection center and node directory, following the user's explicit request for modal selection, a provider-style list of exits that each sign in separately, per-rule exit choice, and Tailscale-based per-node ping. The incumbent visual-world reference, seed:413a3804ca48439d, is retained from this surface's previous contract; the grouped card lists and single-line density follow the user's supplied reference and subsequent corrections.

FINISH: Verify the rendered home and per-exit pickers in English/Chinese, light/dark appearance, and narrow/wide windows. Review the finished flow and document the shipped behavior in DESIGN.md. No raster assets are introduced.

## Boundaries and states

Split's default exit carries proxy matches from builtin/custom sources, `proxy_domains`, `proxy_ips`, `final: proxy`, and bare Tailnet addresses without a more specific route. The unmatched-traffic control remains independent. The optional `main` profile retains its legacy state path; additional exits retain stable IDs and `state_dir/exits/<id>/tailscale` paths, with no promotion into `main` after removal. Removal checks the configuration revision before logout and again before saving. Affected default/global selectors become explicitly unset and require a new confirmed choice; an explicit final-route reference to the removed exit resets to `direct`. Removing `main` also clears its MagicDNS suffixes. Zero-exit drafts preserve the remaining dormant routing policy. Add after removing the last exit creates a new additional profile and leaves both selectors unset until the user confirms a traffic exit. Remote Tailnet record deletion is not implemented because TailSplit has no management authority.

Use existing authenticated loopback APIs and revision-checked configuration writes. Never expose authorization URLs or credentials. Only discovered online list entries can be chosen; retain the configured exit when it is missing or offline, but do not enable unavailable choices or silently choose a replacement. Only an explicit Ping action measures latency; no invented regions, benchmark claims, or automatic best-exit behavior. Preview results are explicitly simulated. Serialize pings, bound their duration, and discard results on network/device identity changes. Protect settings drafts by requiring save/discard before applying connection changes. Settings navigation preserves even invalid YAML drafts. Sign-in, discovery, connect, reconnect, offline, empty, failed, and disconnected states remain distinct. Preserve English/Chinese localization, system appearance, keyboard focus and reduced-motion support. No new dependency, release, commit, or publication is part of this change.
