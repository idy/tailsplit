### Guided setup and cancellation

Service installation, browser authorization, device approval, node selection and connection remain distinct states. An explicit macOS Add exit, Sign in or Connect waits for the exact bundled service build; background discovery, Ping and logout never open Installer. Pending device approval never relaunches sign-in; Check approval performs one bounded read-only refresh when no helper monitors it. Guided Save & connect saves the selected node and current mode's exit together before continuing the original request; unchanged recovered nodes avoid redundant writes. Failed saves and unrelated revisions never start traffic.

Native Connect is claimed once by the native panel or the browser fallback tagged for that request; ordinary panels cannot drain it. Preserve capability-matched fragment/session recovery, shared browser cancellation tombstones and the rule against replaying an already offered, uncertain native request into the fallback. Before setup, request claims and configuration writes, native recovery admission requires exact live write/readback of a non-cancellation probe sized for the real journal entry. Keep the negotiated backup mode and native scope across ordinary reloads, Cookie-only/backup-only recovery, and the independent recovery keeper and host inbox.

Cancellation targets the exact request/operation owner retained through preparation, login, saving and connection; retries leave unrelated later connections intact. Fresh disconnected saves get new operation IDs. Native Cancel/Disconnect confirms the exact journal, shows Canceling connection as unconfirmed and pending before asynchronous retention/delivery, and pauses setup. RetainCancel stores the exact intent in the root-owned host inbox before returning its receipt; retention is independent of renderer lifetime and completion. Missing, malformed, rejected or timed-out receipts leave the pending marker and explanation visible because the journal or a late host call may still cancel. Only an exact completion acknowledgment clears that uncertainty; an already completed target can be acknowledged on retry. Unrelated acknowledgments and late failures cannot clear a newer intent.

After host retention, IPC/HTTP proceeds without waiting for native navigation admission. Every retry attempts host retention; if its receipt fails, IPC/HTTP fallback requires a fresh exact journal confirmation. Historical commitment, cached capability flags and tab-storage history alone never authorize delivery. An already retained host copy remains owned through storage outages and retry failures. Completion releases the UI even if legacy HTTP is stuck. When neither current journal protection nor host retention can be confirmed, keep uncertainty visibly pending without starting unprotected delivery. Missing scope metadata or unavailable recovery stores direct the user to native-menu Disconnect or Quit. Rendering or losing a panel never invents cancellation or stops an established session. Native quick saves check recovery before a Global disconnect/consent prompt and again after consent. DESIGN.md retains the detailed recovery, native-navigation and browser-launch ownership contracts.

### Configuration recovery

An invalid saved configuration retains its diagnostic and offers Edit YAML and Back up & rebuild. If removing only obsolete `dns.listen` yields a strictly valid document, Repair configuration appears first and preserves exits, rules and settings after backing up the source. Rebuild backs up the original in the same folder and restores desktop defaults while retaining device login data. Confirmations explain discarded drafts and disconnecting Global protection; Cancel/Escape leaves file and connection untouched. Confirmed recovery disconnects, uses the operation gate and revision check, and stays disconnected; rebuild returns to empty Exit Nodes with a persistent backup-path notice. Failures preserve the source with retry, and revision conflicts offer Reload. Valid saved documents do not expose recovery even when an unsaved draft is invalid. Reuse shared buttons, dialogs, semantic colors and wrapping banner actions in both languages and appearances.
