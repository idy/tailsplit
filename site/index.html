Keep the route
in your hands.

Manage domain lists, IP ranges, and GFWList rules in the configuration panel or YAML editor.

Use an application’s HTTP/SOCKS proxy settings, or enable TUN routing for captured system traffic. Both modes use the same routing rules.

In rule mode, connections are matched in this order:

  1. Configured Tailnet destinations

    MagicDNS names, configured Tailnet domains, and Tailnet addresses use the embedded Tailscale connection.

  2. Your direct exceptions

    Direct domains, GFWList exceptions, and direct IP ranges stay on your network.

  3. Your proxy rules

    Proxy IP ranges, proxy domains, and GFWList proxy matches use the selected exit.

  4. The remaining traffic

    Other private destinations go direct. Everything else follows your configured default.

DNS is part of the route. Proxy-domain lookups use the proxy exit; Tailnet names use the appropriate Tailnet resolver.

Release notes and all downloads

Install on macOS or Linux.

The installer detects your platform, verifies SHA-256, and installs the app on macOS or the CLI on Linux. It preserves your configuration and device state.

curl -fsSL https://tailsplit.idy.dev/install.sh | sh

For a user-local CLI, add sh -s -- --cli --no-sudo after the pipe. See the installer options.

  1. Open TailSplit.

    Run the Windows EXE installer, or install the macOS app from its DMG. Open TailSplit normally; a new installation starts disconnected in the tray or menu bar.

  2. Allow the network service.

    Windows Setup installs the network service. On macOS, the first connection opens its bundled package installer. An administrator approves the service; the app itself runs normally.

  3. Review your rules. Connect.

    Sign in to your Tailnet, choose an exit and review the routing rules in the window or configuration panel. Device authorization opens your default browser; connecting is a separate action.

Upgrading an older YAML? Remove the obsolete dns.listen field before connecting. Keep your other configuration and device state.

Application proxy

Opt individual apps into the local HTTP/SOCKS proxy. A narrow DNS TUN route is created; the system proxy, default traffic route, and system DNS stay as they are.

System routing

Enable tun.enabled in YAML to add system-traffic routing and DNS interception. Rules apply to connections captured by the TUN.

A little context
before connecting.

Building the macOS app?

With Go 1.26.2 or later, Python 3.11+, and Xcode Command Line Tools, run this from a TailSplit checkout:

make app

This creates an ad-hoc development build. Developer ID signing and notarization use the separate documented release process.

What happens when an exit is unavailable?

Global mode sends captured traffic through the selected exit and keeps the running TUN in place if that exit goes offline. It blocks those connections until the exit recovers.

This protection depends on TailSplit and its TUN remaining active. Disconnecting, quitting, or a background-service crash removes the TUN and temporary DNS, restoring system networking. It is not a persistent system-wide firewall kill switch.

Why does application proxy mode need permission?

Both connection modes create a TUN for DNS. Application proxy mode adds only its narrow DNS route; system routing adds the broader traffic routes. The network service performs this work, and the Windows or macOS installer handles administrator approval.

Does signing in start the proxy?

No. Signing in authorizes the embedded Tailscale device. Starting the proxy is a separate action. Opening the app and automatic connection are also separate preferences; automatic connection is off by default.

Can I choose another exit?

The exit menu lists devices your Tailnet makes available as exits. Offline or expired devices cannot be selected. Switching exits saves the choice and reconnects a running proxy while preserving your device login and routing rules. TailSplit does not silently choose another exit for you.
